Note: one verbose re-run before the harness fix failed the smoke test (40.56s, timeout
waiting for SMOKE: GOT) — a pre-existing test-harness race, not a product regression:
the svc reply can reach the node before the node's own SENT wait finishes, and the
cursor-based waiter never looked back at already-scanned lines. Fixed by making
waitLine check already-seen history first (smoke_test.go). Product code unchanged by that fix.

--- deadlock found by the attack tests (fixed in this change) ---
First implementation of the 64 KiB cap used io.ReadAll on the stream. A libp2p stream
stays open while the sender waits for the ACK, so ReadAll waited for an EOF that only
arrives after the reply — the receiver deadlocked itself. TestResourceV2RateLimits
hung for the full 10-minute test timeout on this bug. Fixed with decodeCapped:
json.Decoder reads exactly one value and returns (the framing), with a byte counter
detecting overflow. After the fix both security tests pass in ~0.6s each.
