# DAIN 제품 설계 원칙 — 최우선 (2026-10-25, 사용자 지시)

일반 사용자가 설치하기 쉽고, 저장공간을 최대한 적게 사용하며, 별도 설정 없이
간편하게 참여할 수 있어야 한다. 이 원칙은 모든 기능 구현보다 우선한다.
이후 구현에서 이 원칙을 위반하는 부분이 있으면 **명시적으로 보고**한다.
이 문서는 원칙과 현재 상태(준수/위반/미비)를 함께 기록한다. 상태는 측정일 기준으로,
코드 변경 시 갱신한다.

## 원칙 9개

1. **개발 도구 불필요**: Mac/Windows/Linux 사용자는 Go·Git·Docker·SSH·VPN 등을
   별도로 설치할 필요가 없어야 한다.
2. **단일 배포 파일**: 프로그램은 가능한 한 단일 배포 파일 또는 간단한 앱 패키지로
   제공한다.
3. **기본 설치는 가볍게**: 기본 설치에는 AI 모델과 불필요한 개발 도구를 포함하지 않는다.
4. **기여량 0% 시작**: 최초 실행 시 CPU·GPU·RAM·스토리지 기여량은 0으로 시작하고,
   사용자가 직접 허용할 때만 자원을 제공한다.
5. **모델 다운로드는 사전 동의**: AI 모델 다운로드가 필요한 경우 용량을 미리 표시하고
   명시적 동의를 받는다.
6. **자동 연결**: 사용자가 IP·포트·Relay 주소를 직접 입력하지 않도록 자동 연결을
   목표로 설계한다.
7. **자동 동작은 알리고 선택하게**: 백그라운드 자동 실행, 자동 다운로드, 자동
   업데이트는 사용자에게 명확하게 알리고 선택할 수 있게 한다.
8. **실측으로 증명**: 설치 용량뿐 아니라 실제 디스크 점유량·메모리 사용량·CPU 대기
   사용률·삭제 후 잔여 파일도 측정한다.
9. **검증 가능한 배포**: 배포 파일에는 SHA-256을 제공하고, 정식 배포 전 코드 서명과
   안전한 업데이트 방법을 마련한다.

## 현재 상태 감사 (2026-10-25, 기준: `experiment/phase-a-relay` @ `0c762aaf`)

### 준수
- **1 (부분 준수 — 배포 경로)**: 사전 빌드 바이너리는 Go·Git·Docker·SSH·VPN 없이
  실행된다. Linux VM에서 크로스 컴파일한 Mac arm64 바이너리가 이를 증명한다
  (아래 실측 참조). 단, 현재 Phase A 테스트 절차 문서에는 Mac에서 Go로 직접
  빌드하는 경로가 남아 있었고, 이번에 사전 빌드 방식으로 정정했다
  (`docs/phase-a-external-test-prep-20261025.md` §4 참조).
- **2 (부분 준수)**: `dain-node`·`dain-relay`는 각각 CGO_ENABLED=0 단일 정적
  바이너리다. 단, .dmg/.msi/.AppImage 같은 간단한 앱 패키지는 없고, GitHub
  릴리스에서 파일을 골라 받는 형태다.
- **3 (준수)**: 기본 `dain-node` 바이너리에는 AI 모델이 포함돼 있지 않고, 엔진
  (llama.cpp)도 별도다. 모델은 `~/.distributed-ai-node/models/`에 사후에 들어간다.
- **7 (부분 준수 — 부재로 인한 준수)**: 자동 업데이트·백그라운드 자동 실행·자동
  다운로드(앱 차원) 기능 자체가 없다. `service/cmd/server`의 VersionInfo는
  "future auto-update의 anchor"라고만 돼 있다. 단, `--api`를 지정하면 30초 간격
  하트비트 등록이 자동으로 돌고, 모델 복제는 백그라운드로 일어난다(원칙 5 위반
  참조). 자동 실행을 도입할 때는 반드시 명시적 선택으로 설계해야 한다.

### 위반 — 명시 보고
- **4 위반 (P0)**: `node/cmd/node/main.go`의 기본값이 CPU 10%·RAM 10%·스토리지
  10%다(GPU만 0%). 최초 실행 0% 시작이 아니다. 일반 배포 전에 기본값을 전부
  0으로 바꾸는 수정이 필요하다. Phase A 테스트는 `--cpu 0 --ram 0 --storage 0`을
  명시해서 우회하고 있다.
- **5 위반 (P0)**: 서비스가 모델을 할당하면 노드가 `OnAssign` →
  `go replicate(mid)` → `materialize.Materialize`로 백그라운드에서 즉시
  다운로드한다(`node/cmd/node/main.go:434-437`, `~448-468`). 용량을 미리
  표시하지도, 동의를 묻지도 않는다. `Materialize`는 manifest의 `SizeBytes`를
  알고 있고 SHA-256으로 검증하지만, 그것은 사후 검증이지 사전 동의가 아니다.
  수정 방향: 할당 수신 시 "모델 X, 용량 Y MB를 받겠습니까?"를 표시하고 동의 후에만
  다운로드하며, 동의 없이는 할당을 거부·보류한다.
- **6 위반 (설계 단계)**: 현재 노드는 `--relay <multiaddr>`, `--connect <multiaddr>`,
  `--api <URL>`을 수동으로 입력해야 한다. 일반 사용자가 따라 할 수 있는 형태가
  아니다. Phase A 외부 테스트는 이 수동 경로로 진행하되, 정식 제품 방향은
  내장 기본 릴레이 주소(부트스트랩) + DNS 기반 발견 + 사용자 확인 없는 주소
  입력 제거다. 단, 내장 주소는 중앙화·검열·단일 장애점 문제를 함께 검토해야 하며,
  릴레이 주소 변경 시 안전한 업데이트 경로(원칙 9)와 묶어서 설계한다.

### 미비 — 측정·절차 부족
- **8 미비 (기준 측정 1회 확보)**: 이번에 기준을 처음 측정했다(아래). 삭제 후 잔여
  파일 측정과 장시간 대기 사용률, 모델 보유 시 디스크 점유량은 아직 측정하지 않았다.
  삭제(언인스톨) 경로 자체가 없다: 노드 데이터는 `~/.distributed-ai-node/`에
  남는다(`identity.key`, `models/`). 삭제 시 남는 파일을 안내하는 문서와, 키·모델을
  지우는 `--uninstall` 또는 삭제 안내가 필요하다.
- **9 미비**: SHA-256은 릴리스 워크플로가 `SHA256SUMS.txt`를 생성하고
  `oracle-setup.sh`가 검증하므로 **부분 충족**이다. 코드 서명(macOS
  서명·공증, Windows 서명), 안전한 업데이트 채널(서명된 매니페스트·버전 고정·
  롤백)은 없다. 정식 배포 전에 마련해야 한다.

## 보안은 기본 구조다 (2026-10-25, 최상위 목표 확정)

보안은 개발 완료 후 추가하는 기능이 아니다. 위 9개 원칙과 같은 층위에
Zero Trust / Default Deny가 있다. 상세는 `docs/security-architecture.md`를
본다. 요약:

- 빈 allowlist는 차단이다. 기본 기여량은 0%다. 사용자 승인 없는 연산
  배정은 없다. 원격 임의 명령 실행은 프로토콜에 없다.
- 자원 상한은 강제할 수 있는 것만 강제한다고 말한다. 강제할 수 없으면
  자동 비활성화하고 그 사실을 표시한다.
- 키 유출 시 철회 절차(allowlist 파일 + 릴레이 재시작)가 동작해야 한다.
- "보안이 완벽하다"는 선언은 하지 않는다. 막은 공격은 테스트 증거로
  말한다 (`node/internal/p2p/security_test.go`).

## 실측 기준 (2026-10-25, Linux VM에서 측정)

사전 빌드 방법: `CGO_ENABLED=0 go build -trimpath -ldflags "-s -w"`, Go 1.26.0,
`experiment/phase-a-relay` @ `0c762aaf`에서 크로스 컴파일. Mac에 개발 도구를
설치하지 않았다.

| 항목 | 실측값 |
|---|---|
| `dain-node` darwin/arm64 | 24,144,562 bytes (~23.0 MiB), SHA-256 `d485a94bc0198a36d6ca1994dd9ed1f88f3448ed85eb06f704735bf60ccd8ea6`, Mach-O 64-bit arm64, PIE |
| `dain-node` linux/amd64 | 24,989,858 bytes, SHA-256 `d730fe36d4e5169b4c991551c4a686f792d1754ed6c61b5e7f4ceb593357fd38` |
| `dain-relay` linux/amd64 | 24,178,850 bytes, SHA-256 `5f5351a81d04e2fa53a6dc964edd887088541d08bbddf5b7848ab79a60593798` |
| 대기 상태(linux node, `--cpu 0 --ram 0 --storage 0`, `--api`·`--connect` 없음, 10초) | CPU 0.0%, RSS 22,072 KB (~21.6 MiB), 스레드 7개, utime 1틱(0.01초)·stime 0 |
| 대기 후 디스크 점유(임시 HOME) | `~/.distributed-ai-node/identity.key` 4.0 KB만 생성. 모델 다운로드 없음 |

보관: Mac 테스트용 사전 빌드 바이너리는 `~/workspace/dain-prebuilt/dain-node-darwin-arm64`
(+ `SHA256SUMS.txt`)에 보관돼 있다. 아직 Mac으로 전송하지 않았다.

주의: 대기 실측은 Linux VM 기준이다. Mac 실기기에서의 대기 CPU·메모리·배터리 영향은
Phase A Mac 테스트에서 별도로 측정해야 한다. 모델 1개(Qwen2.5-0.5B Q4_K_M, 469 MB,
SHA-256 `74a4da8c9fdb…`)를 보유하면 디스크 점유량이 469 MB 늘어난다.

## Phase A 테스트에 적용되는 형태

- Mac에는 개발 도구를 설치하지 않는다. 사전 빌드한 `dain-node-darwin-arm64`만
  전송해 실행한다.
- 테스트 실행은 `--cpu 0 --ram 0 --storage 0` 안전 모드로 하고, `--api`를 지정하지
  않는다(운영 서비스 등록·모델 복제가 일어나지 않게 한다).
- Relay 주소·Peer ID 입력은 이번 실험에서만 허용되는 수동 절차다. 정식 제품에서는
  원칙 6에 따라 제거하는 것을 목표로 하고, 이번 실험의 수동 절차를 일반 사용자
  절차로 오인하지 않는다.
